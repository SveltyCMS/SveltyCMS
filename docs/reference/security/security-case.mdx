# Security Case

This page is the entry point for a buyer, integrator, or reviewer who wants to check security evidence without trusting a summary. Each row points at the file that produces or records the metric, and the machine-readable status lives in [`docs/security/external-validation.json`](../../security/external-validation.json). The status is dated **2026-11-07**. A change to a status must update this page and that JSON record together.

## What this page is for

- It names the gate or document behind each claim, so the claim can be reproduced from the repository.
- It labels self-assessments as self-assessments instead of presenting them as independent findings.
- It shows `pending` where evidence does not exist yet, including the external penetration test.
- It records the review date, so a stale assurance page is visible as stale.

## What this page is not

- It is **not an audit report**. No accounting or security firm has reviewed the controls described here.
- It is **not a certificate**. The project holds no ISO/IEC 27001, SOC 2, or comparable certification, and the OWASP ASVS matrix is a mapping rather than a passed audit.
- It does **not** claim that SveltyCMS is safer than another product. No competitor is named or compared on this page, and no ranking is implied.
- It is **not a substitute for testing your own deployment**. Configuration, hosting, secrets, and integrations determine the effective posture of a running installation.

## Compliance note

Security statements in this repository follow **EU Directive 2006/114/EC** on misleading and comparative advertising and **German UWG §6**. As of 2026-11-07, the rules applied here are:

- every factual claim is dated and links to a source that can be checked;
- self-assessments are labelled as self-assessments;
- no comparative claim is made about another product;
- missing evidence is shown as `pending`, not inferred from adjacent checks.

## AI-assisted security

AI tools assist this project under rules that keep a human accountable for every fix:

1. AI may draft vulnerability triage notes, regression tests, threat-model entries, and advisory text.
2. A named human maintainer reviews and signs every security fix before merge. The signature is the approving review on the change request; automation does not approve security changes.
3. Model output is untrusted input. It is reviewed like any external contribution and is not merged without tests that demonstrate the fix.
4. No secrets, credentials, customer data, or private deployment configuration are sent to a model. Bootstrap secrets stay in `config/private.ts` and are not pasted into prompts, issues, or commits.
