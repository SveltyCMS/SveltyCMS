## 2. Summary of Completed Phases

### Phase 0: Trustworthy Signal, Dual-Baseline Reporting & AST Type Import Analysis

1. **Explicit `CONVENTION_ALLOWLIST` with documented reasons**: Covers SvelteKit hooks/routes/remote functions, 3-pillar widgets (`index.ts`, `input.svelte`, `display.svelte`), dashboard widgets, plugins (`index.ts`, `index.server.ts`, plugin UI slot/column `.svelte` components), email templates, DB adapters, worker entrypoints, design-system UI primitives (`@components/ui/*.svelte`), image-editor tool manifests, reactive search params (`AGENTS.md` §3.10), and the auth entry barrel.
2. **Inline `ImportTypeNode` Tracking**: Integrated AST scanning for `import("./module").Type` syntax (`ts.isImportTypeNode`), recovering 379 inline type edges (such as `setup-types.ts` referenced in `setup.remote.ts`) that previously caused false orphan detections.
3. **3-Counter `--check` Delta Gate**: `evaluateLinkmapGate()` fails strictly on increases in `runtimeCycleCount`, `passThroughBarrelCount`, or `clientServerLeakCount`.
4. **Dual-Baseline Output (`Init │ Gate │ Now │ Net Δ`)**: `linkmap-initial-baseline.json` preserves the pre-optimization baseline so cumulative improvements remain visible on every run, while `linkmap-baseline.json` enforces the ratcheted floor (`0` cycles, `1` pass-through barrel, `0` leaks).
5. **Server-Reachable BFS for Shared Review Candidates**: Computes `serverReachable` from actual server entrypoints (`isServerOnlyPath`) instead of `!staticClientReachable.has(p)`, eliminating false positives where lazy-loaded client modals/widgets caused client-only utilities (`command-palette.ts`, `modal.svelte.ts`, `entry-actions.ts`) to appear as server-shared.
6. **Production API Dispatcher Fix Uncovered by Orphan Scan (`handlers/forms.ts`)**: `src/routes/api/[...path]/handlers/forms.ts` was flagged as an orphan with `0` runtime importers in `src/` because `NAMESPACE_CONFIG` mapped `forms: { handler: "forms", fn: "handleFormsRoutes" }` while `DYNAMIC_HANDLERS` in `src/routes/api/[...path]/+server.ts` omitted `forms: () => import("./handlers/forms")`. Wiring `forms` into `DYNAMIC_HANDLERS` fixed the production `/api/forms/*` 404 bug and connected `handlers/forms.ts` to the server graph.

### Phase 1: All 6 Runtime Import Cycles Broken (`6 → 0`) & Client/Server Boundary

1. **`src/databases/auth/constants.ts` ↔ `src/utils/security/session-cookie.ts`**: The cookie name strings (`SESSION_COOKIE_NAME`, `HOST_SESSION_COOKIE_NAME`, `SECURE_SESSION_COOKIE_NAME`) live in the client-safe `constants.ts`; `session-cookie.ts` imports them from there and `constants.ts` re-exports nothing back, so the edge is one-way.
2. **`src/components/collection-display/schedule-modal.svelte` ↔ `src/utils/modal.svelte.ts`**: Passed `initialAction`, `meta`, and `close` via `$props()` from `DialogManager`.
3. **`src/databases/core/relational-auth.ts` ↔ `src/databases/core/sql-adapter-core.ts`**: Extracted `RAW_DECLINED` and `RawFindResult<T>` into leaf `src/databases/core/drizzle-sql-helpers.ts`.
4. **`src/databases/sqlite/adapter-core.ts` ↔ `src/databases/sqlite/transaction-module.ts`**: Extracted the process-wide re-entrant `Mutex` and `sqliteWriteMutex` into leaf `src/databases/sqlite/write-mutex.ts`.
5. **`src/services/background/jobs/job-queue-service.ts` ↔ `src/services/background/jobs/scheduled-jobs.ts` ↔ `src/services/background/webhook-service.ts`**: Switched `webhookService` in `scheduled-jobs.ts` to a dynamic `await import("../webhook-service")`.
6. **`src/components/system/admin-component-registry.ts` ↔ `src/components/system/builder/input-switch.svelte` ↔ `src/components/system/builder/setting-group.svelte`**: Passed `itemComponent: Self` (`Component<Record<string, unknown>>`) via `controlProps`.
7. **`src/utils/license-manager.ts`**: Loaded `@src/databases/db` and `@src/services/core/settings-service` via dynamic `await import(...)` inside server-guarded functions.
8. **`src/widgets/widget-compatibility.ts`**: Switched default `package.json` import to named `{ version as pkgVersion }`, saving **14 KB** of eager uncompressed JS in the Admin Shell (`2,105 KB → 2,091 KB`).

### Phase 5: Gate Hardening (2026-11-07)

- **Unified AST tier**: `scripts/check/run-ast-gates.ts` runs the tenant-scope lint and the linkmap over one `src` read, replacing two separate processes in `bun run check` (the standalone scripts stay runnable for debugging).
- **Single-owner rule registry**: `scripts/check/rule-registry.ts` declares every fast check once (`id`, script, args, `kind`, `owner`); the runner fails fast on a duplicate id or a missing script, and the date-helper allowlist now has one source of truth shared with `tests/unit/security/invariants.test.ts`.
- **Dead-export authority**: the slop-scanner regex crawler was removed; the linkmap AST is the only dead-export analysis, so the two tools can no longer disagree.
- **Advisory ratchet**: cross-route smuggling, deep relative imports and zombie islands are now gated against `scripts/check/baselines/linkmap-advisory-baseline.json` — they may fall, never rise.
- **Public-API barrel protection**: barrels with runtime consumers are recorded in `scripts/check/baselines/linkmap-public-api.json`; removing one fails the gate (the `smart-table` barrel incident is the motivating case).
- **Incremental extraction**: per-file results are cached by size+mtime in `linkmap-file-cache.json`. `bun run check:linkmap:changed` re-parses only changed files (observed: 1,479/1,492 reused on the second run) and still evaluates the full graph.

### Phase 7: Gates That Make the Phase 6 Wins Non-Recurring (2026-11-07)

Phase 6 improved the tree; Phase 7 makes each improvement enforced. Every item below fails in the ~4 s static tier or in the suite runner itself, not in a 35 s suite that a partial run can report as green.

1. **The client bundle budget is now gated.** `clientReachableKB` / `clientReachableFiles` were reported with `gated: false`, so the preset split could be silently undone. `evaluateLinkmapGate` now enforces a 0.5 % budget (+4 absolute floor): **4,212 KB against a 4,234 KB ceiling**, **454 files against 458**. Shrinking is always allowed.
2. **The server-only boundary is explicit.** `src/services/setup/presets.ts` → `presets.server.ts`. SvelteKit rejects a client import of a `.server.ts` module at build time, and the linkmap classifies it `isServerOnly`, so a re-coupling becomes a `clientServerLeak` violation instead of a silent bundle regression. The client entry point remains `preset-meta.ts`.
3. **The route manifest is validated in the fast tier.** `scripts/check/check-route-manifest.ts` imports `APP_ROUTE_COVERAGE` directly (no second list to drift) and runs the same bidirectional verification as `tests/unit/route-test-coverage.test.ts` — 29 routes / 68 test-file links in ~200 ms. A moved test file now fails at commit time instead of surfacing 35 s later.
4. **Executed test inventory is ratcheted.** `scripts/test/run-unit-suite.ts` emits Vitest's JSON report from the same invocation and `scripts/check/check-test-inventory.ts` floors per-area test counts against `scripts/check/baselines/test-inventory-baseline.json`. Baseline: `unit` **847 files / 8,058 tests across 38 areas**, `components` **53 files / 238 tests**. A vanished area, a lower total, or an empty report fails; growth is free; subset runs print an explicit "ratchet skipped" line.

**Measurement note.** The tracked initial baseline (`linkmap-initial-baseline.json`, 2026-11-07T09:50Z) records **4,250 KB / 443 files**. Against that artifact the verified client-bundle delta is **−38 KB**, not the −47 KB figure quoted in Phase 6 — that number predates the baseline file and is not reproducible from tracked artifacts. The gate uses the tracked artifact, so the enforceable claim is 4,250 → 4,212 KB.

**Verified 2026-11-07:** `bun run test:unit` **847 files / 8,058 tests** · `test:unit:components` **53 files / 238 tests** · client graph **4,202 KB / 456 files** (ceiling 4,251 / 460) · `check:route-manifest` 29 routes / 68 links · media E2E 64/64.

### Phase 8: Explainable, Machine-Readable Gates (2026-11-07)

1. **One definition of module boundaries.** `scripts/lint/lib/module-boundary.ts` owns `isServerOnlyPath`, `isClientEntrypoint` and `SERVER_STUB_PATHS`; `analyze-linkmap.ts` imports and re-exports them. `tests/unit/scripts/module-boundary.test.ts` pins both the classification table and the function identity, so a second copy cannot drift and silently change which modules count as leaks.
2. **Single source for gated counters.** `HARD_GATES`, `HARD_SMELL_GATES`, `ADVISORY_GATES` and `BUDGET_GATES` now drive both `evaluateLinkmapGate` and `compareWithBaseline`. A label can no longer differ between “what failed” and “what was printed”, and adding a counter is a one-line change.
3. **`--explain <file>`.** Answers why a module is client-reachable, server-only, orphaned, allowlisted or a boundary candidate — including runtime importers, static client importers, test importer count, unused exports and smells. `report.explain` carries the same data in JSON. Example: `bun run check:linkmap --explain src/services/setup/presets.server.ts` (server-only, 3 server importers, 0 client importers).
4. **`--json` output.** `analyze-linkmap --json` emits `{ summary, cache, gate, baseline, explain }`; `slop-scanner --json` emits `{ ok, strict, filesScanned, counts, categories, inventoryCategories, autofixedFiles, violations }`. Both keep their exit codes, so CI annotations and dashboards can consume them without parsing ANSI output.
5. **Boundary candidates are ratcheted.** The shared client+server review list (currently **32** modules above 120 LOC) is an advisory: it may fall, never rise. Adding a new shared module requires a reviewed re-baseline, which is the point — it forces a deliberate decision about which side owns the code.

### Phase 9: Two-Process Source Lints (2026-11-07)

The five source rules (`date-helpers`, `silent-catch`, `live-paths`, `transient-classification`, `global-timers`) were five registry entries, each spawning a process and sweeping `src`. Folding them into `check-ast-gates` removed the spawns but made that single process the critical path (**3,311 ms**). They now run as a second AST gate (`scripts/check/run-source-lints.ts`) over one shared read, concurrent with the linkmap:

| Measurement                        |                  Before |        After |
| :--------------------------------- | ----------------------: | -----------: |
| Fast-tier processes                | 6 (5 linters + linkmap) |        **2** |
| `src` tree reads                   |                       6 |        **2** |
| AST gate                           |                3,311 ms | **1,144 ms** |
| Source lints                       |         — (5 processes) | **1,186 ms** |
| `run-fast-checks` total (19 gates) |                3,933 ms | **1,961 ms** |

Two hot rules also gained a cheap pre-gate in their pure cores: `transient` **646 → 106 ms**, `global-timers` **620 → 127 ms** (`silent-catch` 824 → 680 ms; most files contain a `catch`, so its AST pass still dominates). The prefilters only let files through — they never skip a possible match — and every rule keeps its own fixture suite.
