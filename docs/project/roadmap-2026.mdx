## 1. Core Architecture & Performance (Active Backlog)

- **SQLite Write Tail Acceptance Gate**:
  - The SQLite group commit batcher is default ON. Finalize acceptance: achieve a replica run free of 🔴 rows and pass `--strict-variance` across a ≥3-run ensemble.
- **Write-Lane Adaptive Coalescing (2027)**:
  - [x] Shipped adaptive UPDATE lane (`SVELTY_WRITE_COALESCE_UPDATE=1`): an update on an idle gate skips the coalescer scheduler hop; once any mutation is in flight, updates coalesce. Inserts/deletes keep their previous scheduling unless `SVELTY_WRITE_COALESCING=1`. Metrics: `adaptiveUpdates { enabled, immediate, coalesced }`.
  - Evaluate same-tick (`0ms`) vs `1–2ms` insert coalescing windows against 100k and 1M row datasets.
  - Complete the 1M-row PostgreSQL replica proof.
- **Two-Plane Core Phase 5 Verification**:
  - Run 24-hour PostgreSQL soak with 32 concurrent workers on mixed workloads (`LONG_SOAK_HOURS=24`).
  - Demonstrate noise-aware memory leak proof with a flat native residual (`rss - heapTotal - external`) over ≥15-minute steady windows.
  - Publish networked 4-cell matrix separating Cache-Hit (Cell 1) from Origin-Miss (Cells 2 & 3).
  - Add differential wire-vs-domain test coverage for the no-`status`-column fail-closed branch.
- **Multi-Core Cluster Worker Pub/Sub Bridge**:
  - Bridge in-process `graphql-yoga` pub/sub (`entryUpdated`, `yjs:*`, SSE) across workers via Redis Pub/Sub when running under `SVELTY_CLUSTER_WORKERS`.
- **API-Only Build Profile (`bun run build:api`)**:
  - [x] Shipped dedicated headless build profile (`SVELTY_API_ONLY=1`) that stubs `(app)` and `(admin)` UI route modules with zero runtime UI bundle overhead, leaving API, GraphQL, setup, and auth endpoints fully intact.
- **System Copy & i18n Chrome Completion**:
  - [x] Reached 100% localization across all 110 `(app)` files (`bun run check:copy` reporting 0 offenses) across 8 locales (en, de, fr, es, it, nl, pl, ar).
- **Multi-Day Memory Soak**:
  - Execute a 24h+ multi-worker soak row measuring `heapTotal`, `external`, and `arrayBuffers`.
  - Add long-horizon memory profiles for non-SQLite engines (PostgreSQL, MariaDB).
- **Engine-Native Capability Gaps**:
  - Normalise group keys read from JSON extraction types across all SQL adapters to prevent caller post-processing.
  - Harden MariaDB dynamic-field filters (`JSON_UNQUOTE`) against loose type coercion on numeric vs string comparisons.
- **Hardware-Adaptivity Proof On Small Boxes**:
  - Boot the Linux image in a 256 MB / 1 vCPU container and run the seed + read + write lanes — the built server carries platform-native modules, so the container is where "boots in 256 MB" is demonstrated rather than derived.
  - Verify the `index.cjs` heap-cap skip path under Phusion Passenger (the guard is unit-adjacent only; the `PASSENGER_*` branch has no runtime proof yet).
  - Re-measure the lanes with the entry-applied `UV_THREADPOOL_SIZE`: the boot-hook assignment was a runtime no-op until 2026-10-14, so historical local runs used libuv's default of 4 — fs/crypto-heavy paths (media, audit hashing) are the ones expected to move.
  - Publish a small-box row in the comparative ledger (1 vCPU / 512 MB, then 256 MB) so the derived budgets stay a measured column instead of a claim.
  - Add a CI job that runs the profile under `docker run --memory=256m` and asserts the expected tiers, so a future hardcoded budget fails the build.
  - Derive the adapter-node body ceiling for stacks that never launch through `index.cjs` (systemd unit, `node build/index.js` directly), where the 100 MB default still applies.
- **Role-token migration for the remaining admin surfaces**: beyond the wizard, ~294 `src/` Svelte files still paint palette utilities — ≈2 500 paired `surface-*` light/dark classes (concentrated in `config/design-system/+page.svelte`, the widget UIs and older pages; the `input`/`textarea`/`select`/`stepper` primitives are included, so every form inherits them) — plus 38 files / ≈244 legacy-palette usages (`gray-*`/`slate-*` pairs, `bg-white`, `dark:bg-[#0d0f12]`). The setup wizard is fully migrated and documented as the reference (see [style guide](../contributing/style-guide-gui.mdx)); migrate screen by screen with a visual pass, primitives first, and add a budget guard (like `consolidate-shades`) so the raw-class count can only go down.

## 2. Collection Builder & Content Modeling (Active Backlog)

- **Schema Model Relation & Filter Enhancements**:
  - [x] Compile relation operators `some`, `none`, and `every` to capped ID lookups (`RELATION_FANOUT` cap) via `src/services/sdk/namespaces/collections/relation-filter.ts`.
  - Support nested mutations `{ connect, disconnect, create }` with a maximum depth of 2.
  - Implement `onDelete` schema actions (`cascade`, `setNull`, `restrict`) bounded by a fan-out cap of 100.
  - Add virtual field support (`type: "virtual"`) and projection masking (`omit` / `graphql.omit`).
- **Content write & read correctness**:
  - [x] Optimistic locking on entry updates (`If-Match` / `expectedVersion` → compare-and-set, `409 VERSION_CONFLICT` with `details.currentVersion`); legacy writes stay last-write-wins.
  - [x] Revision restore (`POST /api/collections/:c/:id/revisions/:version/restore`) plus bounded pruning (`revisionLimit`, default 100).
  - [x] Filter-path validation (`400 FILTER_UNKNOWN_FIELD`) for unknown keys and unaddressable nested paths.
  - [ ] Access predicate → WHERE fragment merged before count + page (field stripping stays a separate layer).
  - [ ] Draft version row + publish promotion/rollback (reuse `content_drafts`).
  - [ ] `enforceAccess` by default for every CRUD call, with a logged `system: true` escape for system callers.
- **IN PROGRESS — Revisions on by default + draft/live separation (competitive bet #1)**:
  - [x] **Revisions default-on for new collections and setup presets (2026-11-01)**: `revision: true` + `revisionLimit: 100` at creation; explicit `revision: false` preserved; existing unrevisioned files are not rewritten. Collection Builder Define tab has a Revisions toggle/limit, and the save/generator round-trips both flags. Runtime honours any positive limit.
  - [x] Snapshot + restore + `revisionLimit` pruning, optimistic locking, and the `content_drafts` table (existing building blocks).
  - [x] Draft/live separation (2026-11-01): autosave writes `content_drafts` instead of the live row; resume/discard UI; API/SDK draft methods. A draft is **not promoted** on publish (Save writes the live row directly) and there is no draft-version rollback — that promotion/rollback remains open (see the draft-version row above).
    - [x] Storage (2026-11-01): `collectionId` on `content_drafts` across all four adapters, index `(tenantId, collectionId, authorId, updatedAt)`, `ContentDraft.collectionId`, the physical-column allowlist, and the boot ALTER path (spec-driven, no backfill).
    - [x] Adapters (2026-11-01): `getLatestForContent`, `getLatestForCollection`, `upsertDraft`, `deleteForContent` on relational + Mongo with tenant/author scoping; a new-entry draft uses its own UUID as `contentId` and `data.__draft.kind = "new"`; legacy rows (`collectionId` null) stay reachable by entry id; Mongo `update` patches fields and `publishMany` writes the valid `archived` status.
    - [x] API/SDK (2026-11-01): `cms.drafts` (`saveDraft`, `getDraft`, `discardDraft`, `discardDraftsForEntry`) plus the `/api/collections/:id/drafts` routes, fail-closed permissions, drafts never exposed through the list/export/GraphQL lane.
    - Editor: autosave writes the draft, resume shows Restore/Discard, Cancel discards, and a successful Save/Publish discards server-side. **Ship the sink and resume together**; never auto-create an entry on resume (preserve the M1 invariant).
      - [x] Editor half (2026-11-01): `autoSaveDraft` posts to `/api/collections/:id/drafts` (live row untouched, no `_id` stamped); `+page.server.ts` reads the author's latest draft through `cms.drafts.getDraft` and the editor offers Restore/Discard; Save/Publish/Delete/Clone (and Cancel) discard the form's drafts once. See [fields](../reference/components/fields.mdx#autosave-navigation-guard). Publish **promotion** (turning a draft into the live row) is still open.
  - [ ] Migration/opt-in path for collections that already exist without the flag (deliberately not auto-flipped).
  - **Not shipped:** a draft row that is promoted on publish, draft-version rollback, and a migration for existing collections. Do not describe these as available.
- **CMS Tables & List Platform (Smart Table)**:
  - Team & Cloud Saved Views: enterprise tenant-shared view presets with RBAC visibility controls.
  - Observability integration: pipe `list-query-metrics` into continuous benchmark trend reporting.
  - [x] Publish formal operational documentation for Bloom filter thresholds and 404 negative cache eviction (see [cache system](../reference/architecture/cache-system.mdx)).

Dynamic tokens: `$user._id`, `$user.role`, `$tenant.id`. Shipped 2026-10-19 (`src/services/security/access-rule-service.ts`).
  - [ ] Write rules beyond read (create/update/delete per row) and operator support (`$ne`, `$in` beyond arrays, relation traversal).
  - [ ] Admin UI for rule authoring with validation and a preview of the generated filter.

- **Enterprise Identity & Encryption (Shipped 2026-11-04)**:
  - [x] **Enterprise Cloud KMS Envelope Encryption**: Multi-cloud envelope encryption supporting AWS KMS, GCP KMS, Azure Key Vault, HashiCorp Vault, and Local HKDF. Zero-latency in-memory DEK caching ensures sub-microsecond field encryption (<0.008 ms/op, zero network calls on hot paths) preserving sub-2ms persistence. Shipped in `src/utils/security/cloud-kms.ts`.
  - [x] **Enterprise SAML 2.0 & OIDC SSO Federation**: SP-initiated and IdP-initiated SAML 2.0 login (`@node-saml/node-saml`), one-click public provider discovery, RFC 7636 PKCE, JIT auto-provisioning with claim-to-role mapping rules, and OIDC RP-initiated logout.   - [x] **Zero-Overhead Prototype Pollution Defense**: Object utilities (`deepClone`, `deepCopy`, `copyDataWithFreshRowIds`, `deepMerge`, `deepMergeMetadata`, `sanitizeObject`, and `TokenRegistry` path traversal) strictly reject `__proto__`, `constructor`, and `prototype` keys (>5.2M ops/s throughput maintained).
