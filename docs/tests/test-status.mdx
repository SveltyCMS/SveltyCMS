```bash
# Pre-commit parity (format + type gate + risk + unit + real-DOM components)
bun run check
bun run risk:audit
bun run test:unit
bun run test:unit:components

# Before push (mirrors .githooks/pre-push)
bun run gate

# Local database parity (contract suites on every reachable engine)
bun run test:parity
bun run test:parity -- --only=sqlite,postgresql
bun run test:parity:docker            # boot missing engines via compose, then run

# Coverage floors (P0 packages; thresholds in vitest.config.ts)
bun run test:coverage
# Browsable HTML report (opt-in; the v8 HTML reporter is unstable on Windows)
COVERAGE_HTML=1 bun run test:coverage

# E2E flake budget (reads the JSON written by the last Playwright run)
bun run flake:budget
# Measure flakes locally: one retry makes a recovered test visible as `flaky`
PLAYWRIGHT_RETRIES=1 bun run test:e2e -- --grep="(routes/user/)"

# Browser smoke only (reuses build/; auto-rebuilds if source is newer)
bun run test:e2e:smoke

# Unit only
bun run test:unit

# Inner loop — three scopes, pick the smallest that covers your change (Vitest only, never bun:test):
bun run test:unit:area tests/unit/utils/   # 1. fastest (~3.3 s): one dir/file, skips the changed-graph build; extra args forward to Vitest
bun run test:unit:changed                  # 2. selective: unpushed commits + staged + worktree/untracked vs a resolved base.
#                                             Prints the base it chose (@{upstream} → origin/next → origin/main → next → main → HEAD~1,
#                                             pin with --base=<ref>) + the affected file/test count; empty diff or no affected
#                                             test ⇒ loud ⚠️ + exit 0, unresolvable base ⇒ exit 3. Never a silent green.
bun run test:unit                          # 3. the gate (pre-commit): always exhaustive, intentionally NOT selective — never wire a selector into it.

# Build-parity guardrails (static, <1s): config graph aliases, endpoint exports, tenant boundary
bun run test:unit -- tests/unit/config/vite-config-graph.test.ts tests/unit/routes/endpoint-exports.test.ts tests/unit/utils/tenant-module-boundary.test.ts
# NOTE: vitest's `isolate: false` hint is not usable here — cross-file mock/singleton
# leakage fails 37 files / 147 tests (measured 2026-09-18). `--pool=vmForks` is rejected
# too: 2.77 s vs 5.16 s on a 106-file slice, but the full suite failed 2–5 random files
# per run (setup-file `vi.mock` realm + timing) and swung 29.7 s ↔ 71.7 s. Stay on forks.
# Passing tests no longer print captured stdout (`silent: "passed-only"` locally); when
# debugging a passing test's logs, run the Vitest command directly with `--silent=false`.

# Lane router + turbo cache (2026-08-06)
```

## 8. How to keep this page honest

When you ship a meaningful test or stability change:

1. Update **this file** if health, open gaps, or **hot areas** change (few sentences + table rows).
2. Put deep control maps and file-level inventories in **route docs** or [headless-test-inventory](./headless-test-inventory.mdx) — not a separate archive.
3. Never treat static totals as CI truth — GitHub Actions is the live board.
4. After changing a `.svelte` control with a click/keyboard/modal path, run `bun run test:unit:components` and add an interaction test — SSR-only assertions cannot prove it is wired.
