# Test Status

> [!IMPORTANT]
> **Live pass/fail counts = GitHub Actions** on this branch or PR. Numbers in docs drift; CI does not.  
> This page is the **only** test-status dashboard — route maps, inventories, and deep strategy live in the linked docs below (no separate archive).

**Dashboard updated:** 2026-09-19 — **Smart Table platform + test-suite multi-core acceleration & bottleneck elimination wave**. Unit suite **515 files / 4509 tests** green in **18.79 s** (down from 48–54 s, a ~61% speedup via dynamic 16-worker CPU scaling + hot-import decoupling); SQLite integration **660 tests / 71 files** (641 pass, 19 skip without Docker services); the **7-file cross-engine contract bundle is 58/58 on SQLite, PostgreSQL, MariaDB and MongoDB**; `COMPILE_ALL_ADAPTERS=true bun run build` completes (client + server + 4 adapters); `bun run check`, `bun run lint:tenant -- --full` and `risk:audit` **5/5** clean; `bunx tsc --noEmit -p tsconfig.json` reports **0 errors** (was 22). Three static guardrails close failure classes that previously surfaced only in the production build or the secret scanner: the esbuild config graph must stay alias-free, `+server.ts` may export only HTTP verbs + route options, and the private `MULTI_TENANT` flag must stay server-only. Perf: module evaluations are unchanged (~3.2k modules × per-file isolation), but **`tests/unit/setup.ts` was profiled and trimmed** — gating the jest-dom import on a real DOM dropped its per-file cost from **86.5 ms → 3.8 ms**, dynamic worker scaling utilizes available multi-core CPU capacity (`Math.min(16, cpuCount - 4)`), and individual test bottlenecks were eliminated across auth, crypto, and retry loops, dropping full-suite runtime from **48–54 s → 18.79 s** (~61% reduction). `isolate: false` (vitest's "~10 s faster" hint) remains **not** usable here — measured 2026-09-18, 37 files / 147 tests fail from cross-file mock and singleton leakage — but that time is now recovered safely with isolation intact. Two safe wins landed instead: `silent: "passed-only"` now applies **locally too** (passing tests no longer dump captured stdout — `config-cli` JSON, dispatcher request logs — into the terminal; debug with `--silent=false`), and the one un-warmed perf assertion (`filter-worker` 1024×768 < 200 ms) now warms the JIT first, matching the `dashboard-runtime` rule.

## 6. What to run locally

```bash

bun run check
bun run risk:audit
bun run test:unit

# Before push (mirrors .githooks/pre-push)
bun run gate

# Unit only
bun run test:unit

# Inner loop — three scopes, pick the smallest that covers your change (Vitest only, never bun:test):
bun run test:unit:area tests/unit/utils/   # 1. fastest (~3.3 s): one dir/file, skips the changed-graph build; extra args forward to Vitest
bun run test:unit:changed                  # 2. selective: unpushed commits + staged + worktree/untracked vs a resolved base.
#                                             Prints the base it chose (@{upstream} → origin/next → origin/main → next → main → HEAD~1,
#                                             pin with --base=<ref>) + the affected file/test count; empty diff or no affected
#                                             test ⇒ loud ⚠️ + exit 0, unresolvable base ⇒ exit 3. Never a silent green.
bun run test:unit                          # 3. the gate (pre-commit): always exhaustive, intentionally NOT selective — never wire a selector into it.
```
