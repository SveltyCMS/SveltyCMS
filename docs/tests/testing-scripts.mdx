# Testing Scripts Catalog

## CI log policy (quiet by default)

GitHub Actions sets `CI=true` and the workflow sets `CI_QUIET=1`. Together they keep signal high without dropping failure detail:

| Layer                              | Quiet behavior                                                                              | Failure detail                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Bun package cache                  | `actions/cache/restore` + `save` only on miss + success; key `bun-v3-$OS-$bunVer-$lockHash` | digest-mismatch is non-fatal; next successful install re-saves a clean archive |
| oxfmt / oxlint                     | `::group::` collapsed logs; oxlint `--quiet --format=github`                                | full tool exit + annotations on fail                                           |
| Unit (`vitest`)                    | `reporters: [dot, github-actions]`, `silent: "passed-only"`                                 | failed test logs + annotations                                                 |
| Integration (`run-integration.ts`) | `bun test --only-failures`; server stdout buffered                                          | failure list, summary box, preview log tail on fail                            |
| E2E (`playwright`)                 | `dot` + `github` + HTML/JSON artifacts                                                      | expanded failures, `ci-report-playwright.ts` step summary                      |

Local defaults stay verbose. Force quiet locally with `CI_QUIET=1` or `CI=true`.

### Integration / E2E build harness (not Docker alone)

Docker DBs (`docker compose … up`) are necessary for multi-DB matrix runs, but **not sufficient**.
The production preview must include `/api/testing` (seed/reset). A normal `bun run build` **strips** that handler.

| Command                    | Behavior                                                                     |
| -------------------------- | ---------------------------------------------------------------------------- |
| `bun run test:integration` | Always builds with `COMPILE_ALL_ADAPTERS=true`                               |
| `… --no-build` (local)     | Reuses `build/` **if** harness present; **auto-rebuilds** if deploy-stripped |
| `… --strict-no-build` / CI | Fail if harness missing (no silent rebuild)                                  |

Markers checked: `Unauthorized: Testing endpoints are disabled`, `[TestingHandler]` (same as `verify-prod-build-backdoor --mode=bench`).

## Directory Structure

The `scripts/` directory is partitioned into structured domain folders to maintain an enterprise-grade validation and orchestration pipeline:

```
scripts/
├── benchmark-matrix/   # Multi-database micro-benchmark and regression matrix
├── check/              # Static safety & invariant gates (DB safety, bundle size, flake budget, seams, lockfile)
├── ci/                 # CI reporting dashboards and Playwright result analyzers
├── lint/               # Specialized AST and token linters (design tokens, shades, widgets, tenant isolation)
├── probe/              # Runtime probes & network readiness (deploy backdoor, cgroup hardware, wait-for-ready)
├── runs/               # Test runners & harness orchestrators (run-integration, run-e2e, matrix, bench)
├── security/           # Dynamic & static security scanners, fuzzers, SBOM, backdoor verification
├── test/               # Developer test tools & orchestrators (test-doctor, test-smart, test-contract)
└── [root]              # CLI scaffolding, versioning, release wrappers, and system lifecycle tools
```

## Git Hooks

> [!IMPORTANT]
> **Local hooks are enforced** (owner decision 2026-10-24). A commit only lands when format/lint/typecheck, the unit suite and the component interaction suite pass; a push re-runs the CI Unit job (coverage + components + mutation), the build, SQLite integration, DB parity when adapter code changed, and the browser gate. There is no opt-out environment variable.
>
> ```bash
> bun run git commit -m "…"   # ~3–4 min
> bun run git push            # ~8–10 min
> ```
>
> The earlier opt-in policy (2026-10-23) was reverted after two green-local/red-CI Unit runs; the hooks now catch what the CI reporter caught.

### `.githooks/pre-commit` — Format → Lint → Unit (~40s)

Runs before every commit. Steps:

1. **Database safety** — `scripts/check/check-test-db-safety.ts`
2. **Format + lint** — `bun run check` (oxfmt + oxlint)
3. **Lint-staged** — `bun run gate:fast`
4. **Unit tests** — `vitest run` (skipped if only docs changed)

### `.githooks/pre-push` — Build → SQLite Integration (~1.5 min)

Runs before every push. Steps:

1. **Production build** — `COMPILE_ALL_ADAPTERS=true bun run build`
2. **Quality Gate** — `bun run check`
3. **CVE Audit** — `bun audit`
4. **Secret Misuse Scan** — `bun run scripts/security/scan-secret-misuse.ts`
5. **Tenant Isolation Gate** — `bun run test:tenant`
6. **SQLite integration** — `bun test tests/integration/`

### Full DB Matrix (Local Pre-CI) — ~8 min

For 1:1 CI parity, run all 4 databases locally before pushing:

```bash
bun run test:matrix          # SQLite + MongoDB + MariaDB + PostgreSQL
```

Requires Docker containers running (`docker compose -f tests/docker-compose.yml --profile '*' up -d`).
Covers the same adapter matrix CI runs.

## Core Testing Scripts

### `scripts/check/check-route-behaviour.ts` — Behavioural route contract

Scores every route on four contracts (`load-contract`, `failure-path`, `persistence`, `concurrency`) using test evidence that names the route module or a unique URL. Applicability is per route, so redirect stubs are not scored for writing data.

```bash
bun run check:routes                     # table + score
bun run check:routes -- --json          # machine-readable, with evidence per cell
bun run check:routes -- --check --min=99 # CI gate (floor)
```

The gate runs inside `bun run check`. Each cell names its evidence file, so a low score is a work list, not a mystery. Adding a route without tests drops the score below the floor.

### `scripts/lint/lint-trivially-true-assertions.ts` — Ban unfailable assertions

Static analysis over `tests/**` for four shapes that can never fail: literal tautologies, complementary arms, one-of status unions with no negative case, and assertions swallowed by `try/catch`. Runs in `bun run check`.

```bash
bun run lint:trivial-assertions           # add --check in CI (already wired)
```

A deliberate exception needs `// trivial-assert-ok: <reason>` on the assertion line.

### `scripts/runs/run-e2e.ts` — E2E Test Runner

Unified E2E runner with CI and dev modes.

```bash
bun run test:e2e                        # CI mode (production build, :4173)
bun run test:e2e:dev                    # Dev mode (Vite dev server, :5173)
bun run test:e2e:quick                  # CI mode, reuse existing build
bun run test:e2e --dev --grep=login     # Dev mode + filter
```

**CI mode**: Builds with `COMPILE_ALL_ADAPTERS=true`, starts production preview, runs wizard → auth-setup → chromium.
**Dev mode**: Starts Vite dev server, runs Playwright directly. Faster but not CI-identical.

### `scripts/test/test-doctor.ts` — Local Health Check

Prints the real local vs CI gate map, then runs unit + SQLite integration.

```bash
bun run test:doctor                 # unit + SQLite integration
bun run test:doctor --list          # gate map only
bun run test:doctor --unit-only     # skip integration
bun run test:doctor --with-e2e      # also Playwright (CI-parity, reuses build)
```

**Used by**: Manual developer workflow (not in hooks/CI). Prefer this over outdated `ci:local` / `verify:*` names (those scripts do not exist).

### `scripts/test/test-smart.ts` — Smart Test Orchestrator

Git-diff-aware test selector. Analyzes changed files and selects the optimal subset of tests.

```bash
bun run test:smart                     # Auto-detect from git diff
bun run test:smart --all               # Run everything
bun run test:smart --list              # Dry-run
bun run test:smart --suite=auth        # Filter by suite label
```

**Used by**: Manual developer workflow (not in hooks/CI). Unit suites use Vitest; integration uses `bun test` + harness.

### Security unit suite (package script)

Focused hooks security regression (not a separate `security-regression.ts` file):

```bash
bun run test:security
# equivalent: vitest run defense-in-depth + authentication + authorization + file-server-tenant
```

**Used by**: Manual; covered by full unit suite on pre-commit.

### Vitest 5 Developer Workflows (package scripts + raw Vitest)

Vitest 5 introduces high-performance developer ergonomics and smart change execution:

```bash
bun x vitest --watch                   # Interactive TDD watch mode with instant HMR
bun x vitest --ui                      # Vitest Web UI with visual trace viewer (@vitest/ui)
bun run test:unit:changed              # Smart: evaluates git diff and runs only impacted suites
bun run test:unit:area                 # Scoped run on the real Vitest runner (no `svelte-kit sync` step)
bun x vitest run --coverage            # Enterprise P0 coverage gate (outputs to .vitest/coverage)
```

**Features enabled**:

- `fsModuleCache: true`: Filesystem caching of transformed modules for sub-second test turnaround.
- Top-level `forks: { execArgv: ["--enable-source-maps"] }`: Accurate TypeScript stack traces across forks.
- Isolated output directory: Reports and coverage stored in `.vitest/` (ignored by git).

## Security Scripts

### `scripts/security/security-audit.ts` — Unified Security Audit

Master runner that dispatches to engines in `scripts/security/` plus the static scanners:

```bash
bun run security                        # Scanner against localhost:4173
bun run security --auth                 # Build + start server + seed + authenticated scan
bun run security --ci                   # CI mode (exit 1 on findings)
bun run security --base=http://localhost:3000
bun run security --risk                 # Also run global security risk + tenant API scanners
bun run security --secret-scan          # Also run secret misuse scanner (--full)
bun run security --slop                 # Also run code quality slop scanner
bun run security --cve                  # Also run dependency CVE audit (SBOM refresh + bun audit + OSV.dev)
bun run security --full                 # Run ALL scanners (auth + risk + secret + slop + cve + fuzz)
```

**Engines**:

- `scripts/security/auth.ts` — Authenticated audit (builds, starts production server, seeds admin, runs scanner with `--auth`)
- `scripts/security/scanner.ts` — OWASP A01-A07 probes (auth bypass, injection, headers, rate limiting, info leakage)
- `bun audit` + `scripts/security/scan-osv.ts` (via `--cve`/`--full`) — dependency CVE check across GitHub Advisory DB and OSV.dev (20+ feeds), after refreshing `sbom.json`

### `scripts/security/scan-secret-misuse.ts` — Secret Misuse Scanner

Static analysis scanner that detects hardcoded credentials, API keys, and secret exposure in non-server files. Uses a single pre-compiled forbidden-key regex and 32-way parallel file batching. 6 detection rules including **comparison-based backdoor detection** (Rule 6: catches `password === "hardcoded"` patterns that assignment-based scanners miss) and `console.*`/`logger.*` secret exposure checks. Known key formats cover AWS, GitHub, Stripe, Google, OpenAI/Anthropic (`sk-`), Slack (`xox*-`), Hugging Face (`hf_`), JWTs, and private key blocks. Full scans cover `src/`, `scripts/`, `config/collections/`, `.github/` and root build configs; generated `config/private*.ts` is excluded.

```bash
bun run scripts/security/scan-secret-misuse.ts               # incremental scan (changed files)
bun run scripts/security/scan-secret-misuse.ts --full        # scan all files
bun run scripts/security/scan-secret-misuse.ts --strict      # CI mode (exit 1 on medium/high findings)
```

### `scripts/security/scan-security-risk.ts` — Global Security Risk Scanner (entire `src/`)

Static + AST scanner for vulnerability classes in OUR code — the layer no external database can cover. Scans all files under `src/` (vendored `src/types/`, `node_modules`, generated `src/paraglide/` excluded):

| Rule                         | Severity | Detects                                                                                                                      |
| ---------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| SQL value interpolation      | error    | `'${value}'` inside SQL strings — the `author__not_in` SQLi class; line-scoped identifier guard (`assertSafeSqlIdentifier`)  |
| SQL string concatenation     | error    | `"..." + value + "..."` SQL assembly                                                                                         |
| MongoDB JS execution         | error    | `$where` / `$function` / `$accumulator` — server-side JS (RCE class)                                                         |
| Dynamic code execution       | error    | `eval(` / `new Function(` (RCE sinks)                                                                                        |
| SvelteKit CSRF disabled      | error    | `csrf: { checkOrigin: false }` / `csrf: false`                                                                               |
| Non-httpOnly cookie          | error    | `httpOnly: false` (double-submit CSRF cookie exempted by design)                                                             |
| Loopback prefix bypass       | error    | `.startsWith("localhost")` / `.startsWith("127.0.0.1")` without `:` port boundary (matches `localhost.evil.com`)             |
| Tenant header spoofing       | error    | Raw `headers.get("x-tenant-id" \| "x-test-tenant-id")` outside `request-tenant.ts` — must use `resolveRequestTenant()`       |
| Bare `NODE_ENV === "test"`   | error    | Security/auth hooks gating test bypasses on bare `NODE_ENV === "test"` instead of `TEST_MODE` / `PLAYWRIGHT_TEST`            |
| Reverse-proxy IP spoofing    | error    | Raw `headers.get("x-forwarded-for")` in server routes/hooks — must use `getClientIp(event)`                                  |
| Blocking `redis.keys()`      | error    | Synchronous `redis.keys(...)` calls — must use `redis.scanIterator()`                                                        |
| Unbounded batch size (AST)   | error    | API `batch` handlers iterating request arrays without an explicit upper-bound (`<= 100`) guard                               |
| Privilege field / escalation | error    | `updateUserAttributes` without `sanitizeClientUserAttributePatch` / `stripPrivilegeEscalationFields`                         |
| Setup API / complete gating  | error    | `/api/setup` public classification or `handleCompleteSetup` missing `isSetupComplete()` lock                                 |
| Shell command interpolation  | warning  | `exec(\`...${...}\`)` — use execFile/spawn with an args array (`.exec()` DB methods, WAF regex literals excluded)            |
| Path interpolation           | warning  | `fs.*` with member-access `${x.y}` paths or quote-concat — path-traversal class; guarded files + bare locals pass            |
| SSRF                         | warning  | `fetch()` with request-derived URL (configured endpoints like `ollamaUrl`/`this.baseUrl` pass; remote upload requires guard) |
| XSS sinks                    | warning  | `innerHTML=`, `outerHTML=`, `insertAdjacentHTML(`, `document.write(`                                                         |
| Regex interpolation          | warning  | `new RegExp(\`...${x}...\`)` without escaping (escape helpers, `\$&` idiom, constants, `\\${` pass)                          |
| SQL identifier interpolation | warning  | Unescaped identifiers (skipped in files with `assertSafeSqlIdentifier`-style guards)                                         |

```bash
bun run scripts/security/scan-security-risk.ts          # scan (warnings tolerated)
bun run scripts/security/scan-security-risk.ts --strict # exit 1 on errors (pre-commit)
```

### `scripts/security/scan-osv.ts` — Global Vulnerability Check (OSV.dev)

Queries **OSV.dev** — the global aggregator that merges GitHub Advisory DB (GHSA), NVD, and 20+ other feeds — with the purls from `sbom.json` (CycloneDX, kept in lockstep by pre-commit). One batch request covers the whole dependency tree, including SvelteKit/Svelte/Vite advisories. Results cached 24h under `node_modules/.cache/osv-cache.json`.

```bash
bun run scripts/security/scan-osv.ts          # check (24h cache)
bun run scripts/security/scan-osv.ts --strict # exit 1 on any vulnerability
bun run scripts/security/scan-osv.ts --fresh  # ignore cache
```

### `scripts/security/risk-audit.ts` — Full Commit Risk Audit (Parallel 6-Gate Runner)

Runs all 6 fast, stateless security checks **in parallel** in one gate (wired into `.githooks/pre-commit`) with deterministic buffered output and per-step timing:

1. `scan-security-risk --strict` — global scan: DB (4 adapters) + loopback/tenant/test-mode/IP-spoof/AST batch guards + command injection, eval, paths, SSRF, XSS + SvelteKit config
2. `scan-secret-misuse --strict` — hardcoded credentials, comparison backdoors, and `console`/`logger` secret leaks
3. `slop-scanner --strict` — XSS/RTL/security architecture
4. `lint-tenant-api` — AST tenant-isolation API hygiene, `systemScope` brands, and `bypassTenantCheck` allowlist
5. `bun audit` — GitHub Advisory DB (npm tree)
6. `scan-osv --strict` — OSV.dev global database

```bash
bun run risk:audit          # parallel commit gate
bun run risk:audit --full   # force full non-incremental scan on all gates
```

### `scripts/security/slop-scanner.ts` — Code Quality + Security Architecture Scanner

Svelte 5 + Accessibility + RTL + Quality + Security scanner. Catches issues oxlint doesn't cover.

Suppression entries in `.slop-suppress.json` are validated on load and matched by exact path or directory prefix only (never a substring), so one file cannot silently silence a sibling.

**Code quality checks:** XSS (`{@html}`), RTL compatibility, button variant validation, file naming, duplicate content, stale-placeholder tracking.

**Security architecture checks (6 rules):**

| Rule                  | Detects                                                                             |
| --------------------- | ----------------------------------------------------------------------------------- |
| CORS reflection       | `Access-Control-Allow-Origin` reflecting arbitrary `Origin` header with credentials |
| Broad MIME types      | File upload allowlist accepting `application/*` without specific subtypes           |
| Fast hash for secrets | `createHash("sha256")` used on API keys/tokens — should use HMAC                    |
| System user backdoor  | `user._id === "system" && password === "hardcoded"` patterns                        |
| Request body clone    | `request.clone()` without size limits — OOM risk                                    |

**Client/security consistency checks:**

| Check                 | Detects                                                                                                                                                        |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Raw SQL identifiers   | SQL DML/DDL template literals interpolating identifiers without validation (skips Drizzle `sql.raw`/`sql.identifier` and files that already guard identifiers) |
| Mutating fetch + CSRF | `fetch("/api/...", { method: POST/PATCH/PUT/DELETE })` without `X-CSRF-Token` — prefer `fetchApi`/`clientJsonHeaders`                                          |
| RegExp interpolation  | `new RegExp(\`...${input}...\`)` without escaping — regex injection / ReDoS footgun                                                                            |

Use `slop:suppress` in a comment to skip a file.

```bash
bun run slop                              # Check all files
bun run slop --strict                     # CI mode (fail on findings)
bun run scripts/security/slop-scanner.ts --fix     # Check + autofix
bun run scripts/security/slop-scanner.ts --surface # List the advisory inventory
```

Unused exports are classified into **dead-code candidates** (`unused-export` — referenced nowhere in `src`/`scripts`/root/`tests`/`docs`; actionable) and two advisory inventories: **export-surface** (referenced by tests/docs only — test-only reset helpers and documented public API) and **duplicate-export-name** (the same distinctive name exported by several modules — usually a legitimate re-export bridge or remote/server contract symmetry).

The two advisory categories are **not findings**: they are summarised on a separate `🗂️  Inventory:` line, never counted in the `errors / warnings / infos` total, and never affect `--strict`. A clean tree therefore reports `0 errors, 0 warnings, 0 infos` while still tracking the public/test surface. Use `--surface` / `--verbose` (or `SLOP_PRINT_CAP`) to print the inventory.

## Hardware & Environment Probes (scripts/probe/)

### `scripts/probe/probe-hardware-tiers.ts` — Hardware Tier Probe (cgroup)

Self-bundles the real `src/utils/hardware-profile.ts` and runs it inside memory/CPU-limited containers (`--memory=256m --cpus=1`, `--memory=512m --cpus=2`, plus an unconstrained case), asserting the derived budgets exactly: heap, RSS target, L1 caches, body limit, DB pool, workers, threadpool, and the ≤ 70 % invariant. The unit suite injects limits; this gate proves the runtime actually reads the cgroup.

```bash
bun run scripts/probe/probe-hardware-tiers.ts          # needs a reachable Docker daemon
```

**Used by**: CI whitebox job (`08-hardware-tiers`).

### `scripts/probe/wait-for-ready.ts` — Readiness Gate Probe

Zero-dependency TCP and HTTP readiness probe with PID monitoring for preview servers and database ports.

```bash
bun run scripts/probe/wait-for-ready.ts tcp:127.0.0.1:5432 --timeout=90000 --interval=2000
bun run scripts/probe/wait-for-ready.ts http://127.0.0.1:4173/api/system/health --pid=1234
```

### `scripts/probe/probe-adaptive-update-lane.ts` — UPDATE Lane Micro-Benchmark

Measures an idle single update through `NetworkDbQueueGate` twice: coalesced (`SVELTY_WRITE_COALESCING=1`) vs adaptive (`SVELTY_WRITE_COALESCE_UPDATE=1`). Local runs on 2026-10-18 (5 000 samples, 500 warm-up, no database): coalesced **p50 ≈2–3 µs / p95 ≈6 µs / max 2.3–2.5 ms**; adaptive **p50 ≈0.3–0.4 µs / p95 ≈0.5–0.6 µs / max 11–13 µs**. The adaptive lane removes the scheduler hop only when nothing else is queued or in flight.

```bash
bun run scripts/probe/probe-adaptive-update-lane.ts
```

### `scripts/bundle-stats.ts` — Bundle Analytics

Detailed bundle report with gzip/brotli sizes, history tracking.


## Benchmark Scripts (scripts/runs/ & scripts/benchmark-matrix/)

### `scripts/runs/run-core-benchmarks.ts` — CI-Core Benchmarks

Runs the 8 core benchmarks for one or all adapters, then enforces the performance gate.

```bash
bun run scripts/runs/run-core-benchmarks.ts              # All adapters
bun run scripts/runs/run-core-benchmarks.ts --db=sqlite  # Single adapter
```

The gate (`scripts/benchmark-matrix/ci-regression-gate.ts`) compares the current run against
`PERFORMANCE_BUDGET` and a rolling per-adapter baseline. Drift warns at ≥25 % + ≥0.25 ms and
fails at ≥100 % + ≥1 ms, but a severe drift must repeat on the next run (the first observation
freezes the baseline and reports `pending confirmation`). `BENCHMARK_GATE_POLICY=fail|warn`
overrides the default (warn locally and on PRs, fail on `next`/`main` pushes).

**Used by**: CI `bench-core` job.

### `scripts/benchmark-matrix/ci-regression-gate.ts` — Performance Gate

Reads `tests/benchmarks/results/history.jsonl` + `<db>/matrix_metrics.json`, evaluates budgets
and drift, writes `gate-baseline-<db>.json` / `gate-report-<db>.json`, and emits GitHub
annotations + a step-summary table. Severe drift is confirmed across two runs before it fails;
the baseline is frozen in between so one noisy runner cannot re-baseline the metric.

```bash
bun run benchmark:gate --db=sqlite --policy=warn
# or directly:
bun run scripts/benchmark-matrix/ci-regression-gate.ts --db=sqlite --policy=warn
```

### `scripts/verify-benchmark-local.ts` — Local Benchmark Preflight

Blocks local benchmarks when live config uses test DB names.

```bash
bun run verify:benchmark-local
```

| `upgrade.ts`                         | Full SveltyCMS version upgrade (`bun run upgrade`)       |
| `scripts/ci/ci-report-all-green.ts`  | CI dashboard for all-green gate (ci.yml)                 |
| `scripts/ci/ci-report-playwright.ts` | CI reporter for Playwright results (ci.yml)              |

## Git Hook Flow

```
git commit
  └─ pre-commit
       ├─ scripts/check/check-test-db-safety.ts
       ├─ bun run check (format + lint)
       ├─ lint-staged
       └─ test:unit

git push
  └─ pre-push
       ├─ COMPILE_ALL_ADAPTERS=true bun run build
       └─ bun test tests/integration/
```
