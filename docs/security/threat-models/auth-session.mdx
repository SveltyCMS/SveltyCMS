# Threat Model: Authentication & Session

Scope: `src/routes/login/**`, the identity views under `src/routes/(app)/user/**`
and `src/routes/(site)/account/**`, `src/databases/auth/**`, the auth-related hooks
(`handle-authentication.ts`, `handle-authorization.ts`, `handle-token-resolution.ts`,
`handle-rate-limit.ts`, `handle-waf-guard.ts`, `handle-security.ts`),
`src/utils/rate-limit/**` and the auth/token/SCIM handlers.

## STRIDE

| Threat                                                                | Surface                                                                                            | Existing control (file reference)                                                                                                                                                                                                                                                                                                                                   | Residual risk                                                                                                                                                                   |
| :-------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Spoofing** — credential stuffing against a known account            | `src/databases/auth/index.ts`                                                                      | `Auth.authenticate()` counts `failedAttempts` and locks the account for 15 minutes after 5 failures; password strength is enforced by `validatePasswordStrength()`.                                                                                                                                                                                                 | Lockout state is stored per user row; a distributed attacker still consumes the same five attempts.                                                                             |
| **Information disclosure** — email enumeration via login latency      | `src/databases/auth/auth-service.ts`, `src/routes/login/auth.remote.ts`                            | Every `Auth.authenticate()` failure runs **exactly one** Argon2id verification: unknown user, no-password and blocked accounts verify against `DUMMY_ARGON2_HASH`; a wrong password uses the real verify. The caller no longer adds a second dummy hash, so a valid account is not distinguishable by being slower (CWE-208).                                       | The failed-attempt DB write still costs a few milliseconds for a real account; the ~150 ms hash dominates and is constant across failure classes.                               |
| **Spoofing** — session cookie replayed across hosts                   | `src/utils/security/session-cookie.ts`                                                             | Production (secure) mode accepts **only** the `__Host-` cookie; the plain and `__Secure-` names are dev-only fallbacks. `path=/` is forced for the prefixed cookie so the browser does not reject it.                                                                                                                                                               | A deployment with sibling subdomains is protected because a planted `Domain=` cookie is never read in secure mode.                                                              |
| **Tampering** — session data altered client-side                      | `src/databases/auth/session-manager.ts`                                                            | Sessions are server-side records; the client holds an opaque identifier.                                                                                                                                                                                                                                                                                            | A compromised Redis/store credential exposes session records directly.                                                                                                          |
| **Repudiation** — privileged action without an actor trail            | `src/hooks/handle-audit-logging.ts`                                                                | The audit hook records authenticated mutations in the server pipeline.                                                                                                                                                                                                                                                                                              | Failed logins are logged by the auth path, not by the audit hook; correlation depends on log shipping.                                                                          |
| **Information disclosure** — MFA or step-up bypass                    | `src/hooks/handle-authorization.ts`, `src/databases/auth/two-factor-auth.ts`                       | Role-mandated MFA is checked against session AMR; missing enrollment redirects to `/user?tab=security&mfa=required`; WebAuthn lives in `src/databases/auth/webauthn/webauthn-service.ts`.                                                                                                                                                                           | Trusted-device bypass is an explicit product decision whose window is configuration, not code.                                                                                  |
| **Denial of service** — login or token endpoint flooding              | `src/hooks/handle-rate-limit.ts`, `src/utils/rate-limit/**`                                        | Token-bucket lanes key by client and tenant before the login handler runs. The synchronous volumetric pre-filter (`src/utils/rate-limit/l1-filter.ts`, 200 req/s per IP) was removed in `revert(rate-limit)` because it dropped legitimate bulk writes; the lane limiter is the only request-rate control on this surface now.                                      | Single-process counters reset on restart unless the shared store is enabled.                                                                                                    |
| **Elevation of privilege** — role resolution picks the wrong role     | `src/databases/auth/permissions.ts`                                                                | `hasPermissionWithRoles()` resolves role ids/names against the role records and honors the permission bitmask.                                                                                                                                                                                                                                                      | Tenant-bound admins are intentionally not system admins; the distinction is enforced in route guards, not here.                                                                 |
| **Elevation of privilege** — a demoted/blocked user keeps authorizing | `src/services/sdk/namespaces/auth-namespace.ts`, `src/databases/auth/revocation-publish.server.ts` | A patch touching `role`/`roles`/`roleIds`/`isAdmin`/`permissions`/`blocked` invalidates the permission cache, purges every stored session (LRU + store + DB row), and publishes a revocation epoch to the shared cache. Session-cache hits re-check the epoch, so a warm snapshot cannot outlive the change.                                                        | The multi-worker marker is memoized for 5 s per user; a worker that never sees the marker still refreshes the role at the next rotation.                                        |
| **Repudiation** — an IdP-driven logout leaves the session live        | `src/databases/auth/sso-session.ts`                                                                | All three logout paths (RP-initiated, front-channel, back-channel) call `terminateSessionAndMetadata()`: it deletes the session row through the adapter, invalidates the in-process session cache and then drops the SSO metadata. Previously only the metadata was deleted, so the session stayed valid until expiry while the IdP considered the user logged out. | The adapter DELETE is best-effort — if the session store is unreachable the redirect still completes and the session survives until expiry; the failure is logged, not retried. |

## Assumptions

- SSO protocols (`google-auth.ts`, `saml-auth.ts`, `sso-session.ts`) trust IdP metadata fetched over validated TLS; a compromised IdP is out of scope.
- Back-channel logout walks the session store of the process that receives it; the revocation marker extends the guarantee to other workers within the memo window.
- A role sync during OIDC login is treated as a privilege change: caches are invalidated and existing sessions are purged before the new snapshot is minted.
- `SESSION_COOKIE_NAME` and the secure-cookie predicate are the only cookie naming inputs; no handler writes its own session cookie.
