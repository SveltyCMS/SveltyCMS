# Threat Model: Content Write

Scope: collection routes under `src/routes/(app)/[language]/**`, public delivery
under `src/routes/(site)/**`, the collection/content handlers in
`src/routes/api/[...path]/handlers/`, `src/services/sdk/namespaces/collections/**`,
`src/services/content/**` and `src/hooks/handle-collection-write-lane.ts`.

## STRIDE

| Threat                                                                    | Surface                                                                                | Existing control (file reference)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Residual risk                                                                                                                              |
| :------------------------------------------------------------------------ | :------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **Spoofing** — a write is attributed to another tenant                    | `src/databases/crud-tenant-guard.ts`                                                   | Every adapter write carries a tenant scope; `withSystemScope()` in `src/databases/system-tenant-scope.ts` is the explicit bypass and may only be spread when no tenant is set. `bun run lint:tenant-scope` (also part of `check-ast-gates` in `bun run check`) fails an unconditional bypass next to a live `tenantId`.                                                                                                                                                                                                                                                                                 | A system-scoped code path that omits the scope marker is a review item for this surface; the lint gate covers the conditional-spread rule. |
| **Tampering** — payload bypasses schema or field-level rules              | `src/services/sdk/namespaces/collections-namespace.ts`                                 | The namespace resolves the collection schema, sanitizes values, validates numeric ranges and applies field permissions before adapters persist.                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Custom widget validators are part of the trust boundary; a permissive widget widens accepted input.                                        |
| **Tampering** — malicious HTML stored in a rich-text field                | `src/utils/sanitize-html.ts`                                                           | Rich-text output is sanitized through the shared sanitizer; Svelte escapes interpolated strings on render.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Formats that bypass the sanitizer (raw HTML widgets) rely on the widget author's allowlist.                                                |
| **Repudiation** — a mutation has no audit entry                           | `src/hooks/handle-audit-logging.ts`                                                    | The audit hook records collection mutations, including the fast write lane (`serveWarmCollectionWrite`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Direct adapter calls from scripts are outside the HTTP pipeline and outside this log.                                                      |
| **Information disclosure** — a read returns fields the caller may not see | `src/services/sdk/namespaces/collections/read-pipeline.ts`, `src/utils/field-guard.ts` | Read projection and field guards are applied by the SDK namespace; `private`/`hidden` fields are redacted before the response, including nested group/repeater leaves (`fieldDeclaresGuardDeep`). Populated relation targets are fetched with the caller's publication filter and access rules, then redacted with the target schema. Deferred relation warm-up (`scheduleRelationWarmup`) is admin/system-only, capped at 4 fields / 50 ids, and uses `attach: false`; it cannot write a policy-clamped row to the shared cache because the resolver skips caching when `enforceTargetPolicy` is true. | Aggregate or custom query endpoints must use the same projection path to inherit the rule.                                                 |
| **Tampering** — a query-string filter changes the meaning of the query    | `src/utils/collection-query-filters.server.ts`                                         | REST filter leaves are coerced to the declared field type (`coerceFilterValues`); an unparseable boolean/number is `400 FILTER_INVALID_VALUE` instead of an adapter-dependent silent miss. Tenant/ownership/publication clauses are built server-side from typed values and are never derived from the filter.                                                                                                                                                                                                                                                                                          | Filter typing needs the 4-engine contract matrix to pin each driver's behaviour.                                                           |
| **Denial of service** — oversized or pathological query burns the DB      | `src/utils/guarded-query.ts`, `src/hooks/handle-collection-write-lane.ts`              | Write-lane requests pass `wafGuard.inspectEvent()`; query parsing caps page size via `src/utils/api-params.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | A slow but schema-valid filter can still be expensive; index coverage is an operational concern.                                           |
| **Elevation of privilege** — write skips a permission check               | `src/services/sdk/namespaces/collections-namespace.ts`                                 | Mutations call `hasPermissionWithRoles()` with the caller's roles before persistence; the publish gate is evaluated against the stored row.                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Plugin-provided collection hooks run with the caller's scope and can add checks but cannot remove the built-in ones.                       |

| **Information disclosure** — list and point reads disagree on tenant scope | `src/services/sdk/namespaces/collections-namespace.ts`, `src/hooks/handle-collection-read-lane.ts` | Content rows are stored as `"global"` (SQL) or `null` (Mongo) when tenancy is off; the namespace and the read lane treat a null request tenant as unscoped (no tenant filter), so a point read sees the same rows the list returned on both adapter families. System tables keep the `IS NULL` scope in `getEffectiveTenantId`. | Callers that bypass the namespace/lane and pass a raw null tenant to the adapter get the system-scope (`IS NULL`) semantics. |
| **Information disclosure** — a cached list survives a write | `src/services/sdk/namespaces/collections/post-write.ts`, `src/services/cache/response-cache.ts` | Every write (single-entry or bulk) bumps the collection epoch and evicts the collection's list + GraphQL bodies from L1 and shared L2; the point tier is narrowed to the written ids so sibling point reads stay warm. There is no list-preserving write: `entryIds` only scopes the point drop, because the caller cannot know which list bodies embed a field it writes. | A process crash between the durable write and the microtask flush can leave a body until its TTL; a mis-scoped collection name would miss the target list (tenant scope is still enforced by the cache key). |

## Assumptions

- Collection schemas are authored by administrators and validated before activation; a schema authored with `private: false` fields is an explicit configuration choice.
- `handle-collection-write-lane.ts` is the only fast path; reads served from cache are invalidated by the SDK namespace after writes.
- Public site pages render through Svelte templates, not through raw database-to-HTML concatenation.

## Out of scope

- Editor-side rich-text UI state; only the stored value and its sanitisation are in scope.
- Adapter SQL generation, covered by the database adapter contract tests.
