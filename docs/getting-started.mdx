# Getting Started with SveltyCMS

SveltyCMS is the developer-first headless content management system built natively for **Svelte 5** and **SvelteKit**. This guide walks you through scaffolding, local installation, database configuration, and running the interactive first-run setup wizard.

> [!TIP]
> **Why SveltyCMS for SvelteKit projects?**
>
> - **Zero-Serialization Speed**: Server routes call `LocalCMS` directly, running queries in under 2ms without external network latency or GraphQL overhead.
> - **Self-Contained SQLite Default**: Zero setup required to start developing immediately.
> - **Multi-Engine Ready**: Seamlessly switch between SQLite, PostgreSQL, MariaDB, and MongoDB without altering collection schemas.
> - **Full TypeScript Type Safety**: Auto-generated type proxies for collections, entries, and system settings.

New to the product model? Read [Concepts](./concepts.mdx) first — one page, six ideas — then come back and install.

## Install

### Scaffold

```bash
npx create-sveltycms@latest my-cms
cd my-cms
bun run dev
```

Templates match the wizard blueprints: `website`, `blog`, `agency`, `saas`, `corporate`, `ecommerce`. The default database is `sqlite`.

### Clone

```bash
git clone https://github.com/SveltyCMS/SveltyCMS.git
cd SveltyCMS
bun install
bun run dev
```

### Docker

```bash
docker run -d -p 4173:4173 -v svelty_data:/app/config ghcr.io/sveltycms/sveltycms:latest
```

Open `http://localhost:4173`. The image uses SQLite and writes the database and secrets to the `svelty_data` volume.

For the scaffold and the clone, open `http://localhost:5173`. A missing `config/private.ts` opens the wizard at `/setup`. Let the wizard create that file.

Production build and start commands are in [Production deployment](./guides/deployment/production-deployment.mdx).

## Open the wizard

The walkthrough is the [setup wizard walkthrough](./onboarding/setup-wizard.mdx). The six steps are:

1. **Database.** SQLite, or host, port, name, and credentials for PostgreSQL, MariaDB, or MongoDB. Test the connection. Optionally enable Redis caching (and test it), and add regional read-replica connection strings under the advanced options.
2. **Admin account.** Username, email, and a password of at least 8 characters, using upper case, lower case, a number, and a symbol.
3. **Project blueprint.** Pick one blueprint; **Website Starter** is the recommended default. **Country and prices** appears only when you pick the **E-commerce** blueprint — the country starts on Germany and fills currency, shop language, and a suggested tax rate you can edit.
4. **System.** Site name, production URL, timezone, languages, media storage, the collapsible Cloudflare CDN purge fields, then infrastructure mode (multi-tenant, demo).
5. **Email.** Optional. You can set SMTP later.
6. **Review and complete.** The wizard writes the admin user, the collections for that blueprint, and `config/private.ts`, then signs you in.

After that, `/setup` sends you to `/login`, and `/api/setup` answers `403`.

## What you have

With **Website Starter**:

- `http://localhost:5173/` (or port `4173` in Docker) shows the seeded homepage.
- **Pages** contains Home, a legal page, and Privacy. The legal page title follows the country you picked. Replace that text and the privacy text before a public launch.
- Editing a page in the form is included. Inline editing on the live page is the Editable Website plugin (14-day trial). See [Site starter](./development/site-starter.mdx).

The other blueprints are Blog, Agency, SaaS, Corporate, E-commerce, and Blank. What each card creates is the [setup wizard guide](./guides/configuration/setup-wizard.mdx#solution-presets-starter-kits). A card does not turn on the media library, the audit log, or multi-tenant mode — those exist on every install.

A store is the **E-commerce** blueprint, then the Commerce plugin in Extensions. Prices, the order button, and withdrawal are in [E-commerce](./guides/content/ecommerce.mdx).
