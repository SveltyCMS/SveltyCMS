# WebMCP Server Gateway Plugin

Exposes controlled content management and navigation capabilities to remote AI agents via the Model Context Protocol (MCP). Functions as a headless server gateway with configurable transport modes (SSE/stdio), OAuth 2.1 client-credentials authentication, and token limit enforcement.

## Quick Start

1. **Purchase a license** at [marketplace.sveltycms.com](https://marketplace.sveltycms.com)
2. **Configure your license key** in System Settings
3. **Enable the plugin** in System Settings → Plugins
4. **Set transport mode** — choose `sse` for remote or `stdio` for local
5. **Provision an OAuth client** for your AI agent (see below)
6. **Connect your agent** using the MCP endpoint and a Bearer token

| Setting                | Type    | Required | Description                                                     |

## Authentication (OAuth 2.1 client credentials)

Agents obtain a **scoped, expiring, revocable** Bearer token instead of using a
long-lived shared key. Tokens are ordinary SveltyCMS API keys (`sck_…`) minted by
the plugin, so the standard Bearer pipeline enforces tenant binding, expiry, and
revocation.

### 1. Provision a client

Clients are stored as adapter records in the plugin-private collection
`plugin_webmcp_oauth_clients` (one row per client, keyed by `client_id`). Only the
HMAC-SHA-256 of the client secret is persisted. Provisioning is a server-side
helper — call it from an admin-authorized path (CLI or plugin settings), never
from a public route:

```typescript
import { createWebMcpOAuthClient } from "@plugins/webmcp/oauth-clients.server";

const created = await createWebMcpOAuthClient(db, {
  tenantId: "tenant-a", // null in single-tenant deployments
  name: "CI agent",
  allowedScopes: ["webmcp:read", "webmcp:write"],
});
// Present created.data.clientId / created.data.clientSecret to the agent ONCE.
```

### 2. Exchange the credentials

```http
POST /api/webmcp/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id=…&client_secret=…&scope=webmcp%3Aread&expires_in=900
```

- `scope` is optional (space-separated) and limited to `webmcp:read` and
  `webmcp:write`; omitting it grants the client's full allowlist.
- `expires_in` is optional and clamped to **60–3600 s** (default **900**).
- Success returns `{ access_token, token_type: "Bearer", expires_in, scope }`
  with `Cache-Control: no-store`.
- Errors use the OAuth envelope (`invalid_client`, `invalid_scope`,
  `unsupported_grant_type`) with the matching 400/401 status; an inactive
  license returns `403` (`access_denied`).

### 3. Use the token

Send `Authorization: Bearer sck_…` on MCP requests. The token carries the
client's tenant and scopes and expires automatically.

### 4. Revoke

```http
POST /api/webmcp/oauth/revoke
Content-Type: application/x-www-form-urlencoded

client_id=…&client_secret=…&token=sck_…
```

`token_hash` is accepted instead of `token`. Only tokens owned by the
authenticated client in its tenant are revoked; unknown tokens still return
`200` (RFC 7009), and the token is never echoed.

### Legacy `agentApiKey`

The static key remains supported for backward compatibility: send it as
`client_secret` with no `client_id` (or `client_id=webmcp-legacy`) to exchange it
for a short-lived scoped token. New integrations should provision OAuth clients
instead.

## Security

- **Draft-by-Default**: All content mutations from AI agents save as `draft` — human review required to publish
- **OAuth 2.1 Client Credentials**: Short-lived scoped tokens; only HMACs of client secrets are stored
- **Tenant Isolation**: Tokens are bound to the tenant recorded on the client
- **Sandbox Compliance**: MCP tools operate within plugin sandbox boundaries (100 queries, 5s timeout)
